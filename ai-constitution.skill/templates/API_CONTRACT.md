# API 接口约定（API_CONTRACT）

> **本文件是契约，不是建议。**
> 重要：**任何 Agent 都不能修改这些接口！**
> 如需修改，必须：更新此文档 + 人工批准。

> ⚠️ **模板状态声明**：本文件当前内容为**示例占位**，用于演示契约的写法。
> **首次实施前，人类必须将内容与真实实现对齐**，并删除本段声明；
> 对齐之后，契约正式生效——此后任何修改都必须走下方「接口修改规则（铁律）」。

---

## 📦 通用约定

- 协议：HTTPS
- 基础路径：`/api/v1`（占位，以实际为准）
- 数据格式：JSON（`Content-Type: application/json`）
- 时间格式：ISO 8601（如 `2026-08-14T14:29:00Z`）
- ID 格式：UUID v4
- 错误响应统一结构：

```json
{
  "error": {
    "code": "USER_NOT_FOUND",
    "message": "用户不存在",
    "request_id": "uuid"
  }
}
```

## 👤 用户模块（`/api/users`）— 示例占位

### POST /users — 创建用户

请求：

```json
{
  "username": "string",
  "email": "string"
}
```

响应（201 Created）：

```json
{
  "id": "uuid",
  "username": "string",
  "email": "string",
  "created_at": "ISO8601"
}
```

### GET /users/{id} — 查询用户

响应（200 OK）：

```json
{
  "id": "uuid",
  "username": "string",
  "email": "string",
  "created_at": "ISO8601"
}
```

## 🔒 接口修改规则（铁律）

| 规则 | 说明 |
|---|---|
| 1 | **任何 Agent 不能修改已发布的接口** |
| 2 | 必须修改时：先在本文件提出变更草案 |
| 3 | 变更草案必须说明：原因、影响范围、迁移方案 |
| 4 | 等待**人类批准**后才能实施 |
| 5 | 批准后：先更新本文件，再改代码，最后发变更记录 |

> 违反以上规则 = 违反宪法。
