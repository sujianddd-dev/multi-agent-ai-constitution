# 风险分级响应 Playbook（RISK_PLAYBOOK）

> **本文件是护栏，不是说明书**：把"出事了怎么办"提前写成**可判定、可执行、可复盘**的动作。
> 依据：上游工程信条《DOCTRINE》§5——承认 vibecoding 的"隐蔽负债"，流程必须有护栏。
>
> **两条铁律**：
> 1. **没写下来的护栏等于没有**——触发条件、处置动作、责任人、时限，四样缺一不可。
> 2. **复盘必须产出防复发动作**——只写"下次注意"不算复盘。

|---|---|---|---|---|
| **P0 红线** | 数据丢失 / 资金受损 / 安全漏洞 / 隐私泄漏 / 不可逆误操作：`<填具体指标与阈值>` | `<角色>` | 立即 | **立即回滚** |

## 🆘 P0 红线 — 立即止损（先止血，后分析）

**动作顺序（照做，不要跳步）：**

1. **停止写入与放量**：关闭相关开关 / 暂停任务 / 停止灰度放量
2. **回滚**：执行 `<回滚方式：revert PR / 切回上一版本 / 恢复备份>`
3. **隔离现场**：保留日志、快照、错误样本；**不要**在定位前清理数据
4. **通知人类**：`<通知渠道与格式>`
5. **禁止**：在 P0 期间做"顺手优化"或"批量修复"（会污染现场）

**通知模板（复制后填）：**

```
【P0】<一句话现象>
时间：YYYY-MM-DD HH:MM ｜ 影响面：<用户/数据/资金>
已做：<停止写入/回滚/隔离>
待定：<需要人类拍板的事项>
证据：<日志或快照位置>
```

**复盘（24h 内，写入 DECISION_LOG）：** 根因 / 时间线 / 影响面 / 处置 / **防复发动作（测试/护栏/流程/文档）** / 责任人与时限。

---

## ⚠️ P1 严重 — 暂停放量，定位后热修或保持回滚

1. **先回滚止血**，再定位（止血优先于根因分析）
2. 确认影响范围：哪些分层 / 哪些功能 / 是否仍在扩大
3. 热修必须**同时**给出复现测试；无测试的热修视为未完成
4. 48h 内记 ADR：**"下次如何更早发现"**必须写清楚（新增监控项 / 收紧阈值 / 增加检查）

---

## 🔸 P2 一般 — 登记、排期、不阻塞

1. 登记 issue：现象 / 复现步骤 / 影响 / 预期
2. 排期修复；同类问题**重复出现 ≥2 次**则升级为 P1 处理
3. 汇总进下轮复盘
