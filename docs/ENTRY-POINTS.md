# 入口约定（ENTRY POINTS）— 让每个 Agent 都自动读到同一份宪法

> 宪法的价值取决于"**新 Agent 是否会自动读到它**"。
> 本文说明：规则应该放在哪两层、各工具有什么约定、以及怎么验证。

---

## 一、两层放置（关键区分）

| 层 | 放什么 | 放哪 | 覆盖面 |
|---|---|---|---|
| **L0 协议层** | **协作协议**：先读什么、怎么动手、怎么交接、只提 PR。**不含任何项目内容** | 每个 Agent 工具的**全局**指令文件 | 跨项目、跨模型：一次配置，处处生效 |
| **L1 宪法层** | **项目内容**：目标、架构、接口契约、决策、当前任务 | 项目仓库根目录（随 git 走） | 仅该项目 |

> 只做 L1（把 AGENTS.md 放进项目）是不够的：换个项目、换个工具就断档。
> 只有 L0 也不够：它不知道你在做什么项目。**两层配合才稳定。**

---

## 二、各工具的入口约定

| 工具 | 全局指令文件 | 项目级入口 | 备注 |
|---|---|---|---|
| **Codex** | `~/.codex/AGENTS.md` | `AGENTS.md`（自动发现） | AGENTS.md 是社区开放标准 |
| **DSH** | `~/.dsh/AGENTS.md`（用户级，自动注入**每个会话**） | `AGENTS.md` 或 `CLAUDE.md`（候选顺序） | 会向上寻找项目根；两者都存在时以候选顺序为准 |
| **Claude Code** | `~/.claude/CLAUDE.md` | `CLAUDE.md` | 本模板附 `CLAUDE.md`，仅 3 行指向 `AGENTS.md`，避免规则重复 |
| **Copilot** | 仓库/组织设置 | `AGENTS.md` / `.github/copilot-instructions.md` | 同样认 AGENTS.md 标准 |
| **Cursor / Gemini / Kimi Work / zcode 等** | 各自配置目录 | 多数支持 `AGENTS.md` | ⚠️ 各家约定会变，**以实测为准**（见下） |

### 不确定某工具读什么？让它自己说

新开一个会话，第一句问：

> 你启动时自动加载了哪些项目级指令文件？请列出实际读取到的路径。

把观察结果补进上表（提 PR）——**这张表应该由实测维护，而不是靠猜**。

---

## 三、L0 全局协议文件建议内容（3～5 行就够）

全局文件**不要**写项目细节，只写"遇到任何项目都适用的铁律"：

```markdown
# 全局协作协议（适用于我参与的所有项目）

1. 开工前：先读目标仓库根目录的 `AGENTS.md`，再按它的必读顺序读完宪法文档。
2. 接手已有工作时：**第一件事读 `STATE.md`**（当前进度/下一步/阻塞），不要凭聊天记录推断。
3. 改任何东西：走分支 + PR，不直接推 main；PR 描述按 `.github/PULL_REQUEST_TEMPLATE.md` 的"交接五问"写。
4. 每轮收尾：更新 `STATE.md`（接力棒）与本轮验收结果——**不更新视为本轮未完成**。
5. 不确定就保守：先问、先提 PR 草案，不做破坏性操作。
6. 本地记忆（工具自带的 memory/会话历史）只能当加速器，**不得作为交接依据**。
```

对应文件位置（按你的实际工具链添加）：

- `~/.dsh/AGENTS.md`
- `~/.codex/AGENTS.md`
- `~/.claude/CLAUDE.md`

---

## 四、验证清单（配置完跑一遍）

- [ ] 在**一个新项目**里开新会话，问它"你读到了哪些指令文件？"——应能说出 `AGENTS.md`
- [ ] 在**一个已有项目**里开新会话，问它"当前任务是什么、下一步做什么"——应答出 `STATE.md` 的内容
- [ ] 换一个模型（同工具或不同工具）重复上面两步——答案应一致
- [ ] 故意让 `STATE.md` 过时一天，看新 Agent 是否会指出"这页可能过期了"（不会的话，说明协议铁律没进全局层）
